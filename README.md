# ทะเบียนคุมอุทธรณ์จัดซื้อจัดจ้าง

เว็บแอปทะเบียนคุมเรื่องอุทธรณ์ แยกตามปีงบประมาณ ติดตามสถานะ และสืบค้นแนววินิจฉัย
ฐานข้อมูล **Firebase Firestore (แพ็กเกจฟรี Spark)** · วางเว็บบน **GitHub Pages (ฟรี)**
ระบบผู้ใช้แบบง่าย: ผู้ดูแลสร้างชื่อผู้ใช้/รหัสผ่านให้เจ้าหน้าที่ในหน้าเว็บ ไม่ต้องใช้อีเมล

## ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html`, `style.css`, `app.js` | ตัวเว็บ ไม่ต้องแก้ |
| `firebase-config.js` | ค่าโปรเจกต์ `appeal-register-r7` ใส่ไว้ให้แล้ว แก้ `ORG_NAME` ได้ถ้าต้องการเปลี่ยนชื่อหน่วยงานบนหัวเว็บ |
| `firestore.rules` | กฎฐานข้อมูล คัดลอกไปวางใน Firebase Console |

---

## ขั้นที่ 1 สร้างฐานข้อมูล Firestore

(โปรเจกต์ Firebase และ Web app สร้างไว้แล้ว)

1. เข้า https://console.firebase.google.com › เลือกโปรเจกต์ **appeal-register-r7**
2. เมนูซ้าย **Build › Firestore Database** › **Create database**
3. Location เลือก **asia-southeast1 (Singapore)** (เลือกแล้วเปลี่ยนไม่ได้)
4. เลือก **Start in production mode** › Create
5. ไปแท็บ **Rules** ลบของเดิมทั้งหมด วางเนื้อหาไฟล์ `firestore.rules` แล้วกด **Publish**

ไม่ต้องเปิด Authentication

## ขั้นที่ 2 ทดสอบในเครื่อง (localhost)

เปิด `index.html` ด้วยการดับเบิลคลิกไม่ได้ ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ในเครื่อง

- **Python:** เปิด Command Prompt ในโฟลเดอร์นี้ พิมพ์ `python -m http.server 8000` แล้วเปิด `http://localhost:8000`
- **VS Code:** ติดตั้ง extension **Live Server** › คลิกขวา `index.html` › Open with Live Server

ครั้งแรกที่เปิด ระบบจะขึ้นหน้า **"สร้างบัญชีผู้ดูแลคนแรก"** ให้ตั้งชื่อผู้ใช้และรหัสผ่านผู้ดูแลได้ทันที
หน้านี้จะขึ้นครั้งเดียวตอนฐานข้อมูลยังไม่มีผู้ใช้ จึงควรสร้างผู้ดูแลทันทีหลังวางกฎในขั้นที่ 1

ข้อมูลที่บันทึกตอนทดสอบเข้าฐานข้อมูลจริง ลบเรื่องทดสอบได้จากหน้าเว็บ

## ขั้นที่ 3 วางเว็บบน GitHub Pages

1. เข้า https://github.com › **New repository** › ตั้งชื่อ เช่น `appeal-register` › เลือก **Public** › Create
2. กด **uploading an existing file** › ลากไฟล์ `index.html`, `style.css`, `app.js`, `firebase-config.js` ลงไป › **Commit changes**
3. **Settings › Pages** › Source: **Deploy from a branch** › Branch: `main` / `(root)` › Save
4. รอ 1–2 นาที เว็บจะอยู่ที่ `https://<ชื่อผู้ใช้ GitHub>.github.io/appeal-register/`

ไม่ต้องตั้งค่าโดเมนใน Firebase เพิ่ม

## ขั้นที่ 4 สร้างผู้ใช้ให้เจ้าหน้าที่

1. ล็อกอินด้วยบัญชีผู้ดูแล › กด **จัดการผู้ใช้**
2. กรอกชื่อผู้ใช้ (a–z, 0–9 เช่น `somchai`) รหัสผ่านเริ่มต้น ชื่อ–สกุล และสิทธิ์ › **สร้างผู้ใช้**
3. แจ้งชื่อผู้ใช้และรหัสผ่านให้เจ้าหน้าที่ เจ้าหน้าที่กด **เปลี่ยนรหัสผ่าน** เองได้หลังล็อกอิน

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| ผู้ดูแล (admin) | ทุกอย่าง รวมถึงลบเรื่องและจัดการผู้ใช้ |
| ผู้บันทึก (editor) | เพิ่ม แก้ไขเรื่อง ค้นหา ส่งออก |
| ดูอย่างเดียว (viewer) | ค้นหา ดู ส่งออก |

ในหน้าจัดการผู้ใช้ ผู้ดูแลทำได้:
- **เปลี่ยนสิทธิ์**: เลือกจากช่องสิทธิ์ มีผลทันทีแม้ผู้ใช้เปิดหน้าเว็บอยู่
- **ตั้งรหัสใหม่**: เมื่อผู้ใช้ลืมรหัสผ่าน
- **ยกเลิกสิทธิ์**: ผู้ใช้หลุดออกจากระบบทันที กด **คืนสิทธิ์** ได้ หรือ **ลบบัญชี** ถาวร

ล็อกอินแล้วระบบจะจำไว้ในเครื่องนั้น ไม่ต้องล็อกอินใหม่ทุกครั้ง จนกว่าจะกด "ออกจากระบบ"

## ข้อควรรู้เรื่องความปลอดภัย

ระบบนี้ออกแบบให้ใช้ภายในแบบง่าย ตามที่ต้องการ
- รหัสผ่านเก็บแบบแฮช (ไม่เก็บตัวรหัสจริง) แต่การตรวจชื่อผู้ใช้/รหัสผ่านทำในหน้าเว็บ
- ผู้ที่มีความรู้ด้านเทคนิคและรู้ค่าใน `firebase-config.js` (ซึ่งเปิดเผยบน GitHub) สามารถอ่านหรือแก้ฐานข้อมูลได้โดยตรงโดยไม่ผ่านหน้าล็อกอิน
- จึง**ไม่ควร**ใช้เก็บข้อมูลลับหรือข้อมูลส่วนบุคคลที่อ่อนไหว และควรส่งออก CSV สำรองไว้สม่ำเสมอ
- Firebase อาจส่งอีเมลเตือนว่ากฎฐานข้อมูล "ไม่ปลอดภัย" เป็นเรื่องที่คาดไว้แล้วจากการออกแบบนี้
- ถ้าต้องการความปลอดภัยเพิ่มภายหลัง เปลี่ยนไปใช้ Firebase Authentication ได้โดยไม่ต้องย้ายข้อมูลเรื่องอุทธรณ์

## โควตาฟรี พอสำหรับ 15–20 คนไหม

แพ็กเกจ Spark ให้ต่อวัน: อ่าน 50,000 ครั้ง เขียน 20,000 ครั้ง พื้นที่ 1 GB
- ทะเบียน 500 เรื่อง × 20 คน × เปิดวันละ 3 ครั้ง ≈ 30,000 ครั้งต่อวัน → **พอ** (มีแคชในเครื่องช่วยลดอีก)
- 1 เรื่องใช้พื้นที่ราว 2 KB → 1 GB เก็บได้หลายแสนเรื่อง
- ถ้าเกินโควตา ระบบหยุดจนประมาณ 14:00–15:00 น. (เวลาไทย) ของวันถัดไป ไม่มีการเรียกเก็บเงิน

## สำรองข้อมูล

กด **ส่งออก CSV** › เลือก "ทุกปี" ก่อนกด จะได้ไฟล์ทั้งทะเบียน เปิดใน Excel ได้ แนะนำให้ผู้ดูแลส่งออกเก็บไว้เดือนละครั้ง

## ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| หน้าเว็บขาว ไม่ขึ้นอะไร | เปิดผ่าน localhost หรือ GitHub Pages ไม่ใช่ดับเบิลคลิกไฟล์ / กด F12 ดูแท็บ Console |
| "ฐานข้อมูลปฏิเสธการเข้าถึง" | ยังไม่ได้วางกฎและกด Publish ในขั้นที่ 1 |
| "เชื่อมต่อฐานข้อมูลไม่ได้" | ยังไม่ได้สร้าง Firestore Database (ขั้นที่ 1) หรือไม่มีอินเทอร์เน็ต |
| ลืมรหัสผ่านผู้ดูแลคนเดียวในระบบ | Firebase Console › Firestore › Data › คอลเลกชัน `users` › เลือกบัญชีผู้ใช้อื่นที่จำรหัสได้ › แก้ field `role` เป็น `admin` แล้วให้คนนั้นกด "ตั้งรหัสใหม่" ให้ผู้ดูแลเดิม (แนะนำให้มีผู้ดูแลอย่างน้อย 2 คนตั้งแต่แรก) |
| แก้ไฟล์ใน GitHub แล้วเว็บไม่เปลี่ยน | รอ 1–2 นาที แล้วกด Ctrl+F5 |
